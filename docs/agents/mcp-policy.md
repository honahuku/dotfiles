# MCPの利用条件

- **MCP経由で実行する時系列データのクエリ・検索・分析は、既定を直近7日とし、無断で広げない。** 例外は、その確認事項についてユーザーが「MCP経由で実行すること」と「対象期間」の両方を明示した場合だけ。貼られたクエリ、添付CSV、過去の議論、本人が実行した期間は例外の許可にならない。提示するだけのNRQL・SQL等の期間は会話の文脈で決めてよい。実行前の確認は本書の「クエリ実行の期間」に従う。

## クエリ実行の期間

- 実行前に、対象の確認事項・実行方法・期間の許可を照合する。「60日で実行した」「この結果も調べて」だけではMCPで60日を問い合わせる許可にしない。明示許可がなければ直近7日を指定し、より短い期間で足りる場合やツールの上限が短い場合は短い方を使う。
- 期間はNRQLの`SINCE` / `UNTIL`、SQLの時刻条件、`start_time_ms` / `end_time_ms`等、実際に実行される入力へ明示する。内部既定の30日、自然言語から生成される未確認のクエリ、取得したダッシュボードの期間指定に任せない。設定一覧・定義の取得だけで時系列データを問い合わせない操作は対象外。
- 絶対日時、サブクエリ、比較期間、再試行・分割取得も含めて対象期間を確認する。7日ずつ分割して60日を取得することや、結果が0件だから期間を延ばすことも明示許可なしでは行わない。`LIMIT`やタイムアウトは対象期間や課金額の上限の代わりにしない。
- hookや承認審査で拒否された場合は、7日以内の必要な問い合わせへ直す。別名・別ツール・直接API・サブエージェントへ切り替えて制限を迂回しない。7日を超える調査が必要なら、対象事項・MCP経由・期間を示して許可を得る。

## Notion

- Notion MCPは、ユーザーがNotionの操作を明示した場合、もしくはすべて・なんでもMCPやツールを使っていい、と明示された時だけ使用する。
- 基本的には読み取りのみの実行とし、**絶対にユーザーの合意なく書き込みや変更・削除の操作を行わない。**
- デイリーノートの保存先は設定済みのObsidian vaultを使う。デイリーノートの作成・更新・検索でNotionを使わない。
