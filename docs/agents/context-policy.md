# 指示・メモリ・スキルの置き場所

- 共通指示・自主管理スキル・公開可能な設定・背景・手順は公開dotfilesの用途に合うAGENTS.md・スキル・docsに置く。非公開repoには公開できない会社・個人・環境固有の情報に加え、公開側で作業するために非公開に保つ必要がある運用条件・検査手順と、必要な読込条件・公開資料への参照を残せる。情報を削らず用途ごとのdocsへ分割し、非公開側のファイルと記述を最小限にする。全ファイルの実体をいずれかのrepoにコミットする。
- スキルの変更にはLefthookの秘密情報検査を適用する。公開側では禁止語・日本語検査も適用し、vendir取得先の扱いはAGENTS.mdに従う。非公開側の検査条件は、そのリポジトリのhook定義で確認する。

- 全作業に必要な短い規則だけをAGENTS.mdへ置く。特定作業の手順はスキルへ置く
- 公開可能な過去情報は対応スキルの`references/`へ置く。社内・個人の記録は非公開資料へ置き、必要なときだけ読む
- Coding Agentsが自動生成するローカルメモリを手作業の一次情報にしない。重要な規則はAGENTS.mdかスキルへ残す
- ツールが自動生成するディレクトリは、実環境で確認した構造を保つ。独自のサブディレクトリを追加したり、未生成のプロジェクト用パスを命名規則から推測して作ったりしない
- メッセージ送信などの下書きをテキストファイルに書き出すよう依頼された場合でも、具体的なコードや再利用する成果物でない書き捨てのテキストは、対象タスクの詳細に書き込む。ファイル作成は、タスク詳細では扱えないコードや単独で参照・編集する成果物などに限る
## 個人用の改善に着手する前の確認
- 個人用の運用やツールを改善するときは、非公開資料`~/.agents/docs/work/context.md`の`global-policy`を読み、時間帯の規則と例外を適用する。継続依頼でも作業前に日本時間の現在日時を確認する。
- Obsidian vaultなど環境固有の編集・バックアップ方法も、同資料の`global-policy`に従う。
- 共通指示・スキル・hookの呼称と配置は、`write-agent-instructions`の判断手順に従う。
