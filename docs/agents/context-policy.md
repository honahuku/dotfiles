# 指示・メモリ・スキルの置き場所

- 共通指示・自主管理スキル・汎用処理・公開可能な設定は公開dotfilesに置く。本人固有の許可・判断理由や環境に関する規則も、秘匿事項がなければ公開側に置く。変更前に処理と入力値を分け、非公開側へ残す情報とその秘匿理由を具体的に確認する。新規作成だけでなく、既存の非公開ファイルへの追記にも適用する。会社固有の知識・個人情報・秘匿すべき環境設定だけを非公開repoで管理し、全ファイルの実体をいずれかのrepoにコミットする。
- 非公開の値を必要とする処理は、公開側に設定を受け取る入口を設ける。公開用のテスト・期待値・説明例は実在の非公開データから作らず、独立した架空の値を使う。
- スキルの変更にはLefthookの秘密情報検査を適用する。公開側では禁止語・日本語検査も適用し、vendir取得先の扱いはAGENTS.mdに従う。非公開側の検査条件は、そのリポジトリのhook定義で確認する。

- **Obsidian vault `<Obsidian vault>` 配下は、`daily/`・`inbox.md`を含めてメインvaultを直接編集する。** worktree原則と`apply-git-strategy`の適用対象から除外し、編集ごとの手動commit・pushは行わない。保存後のバックアップには`tasks vault-backup`を使う。Obsidian以外のGit管理ファイルには従来のworktree原則を適用する。
- 全作業に必要な短い規則だけをAGENTS.mdへ置く。特定作業の手順はスキルへ置く
- 公開可能な過去情報は対応スキルの`references/`へ置く。社内・個人の記録は非公開資料へ置き、必要なときだけ読む
- Coding Agentsが自動生成するローカルメモリを手作業の一次情報にしない。重要な規則はAGENTS.mdかスキルへ残す
- メッセージ送信などの下書きをテキストファイルに書き出すよう依頼された場合でも、具体的なコードや再利用する成果物でない書き捨てのテキストは、対象タスクの詳細に書き込む。ファイル作成は、タスク詳細では扱えないコードや単独で参照・編集する成果物などに限る
## 端末への反映確認

公開・非公開のdotfilesをCoding Agentsが更新した場合は、mainへの取り込みを確認した後、実際の配置を管理するmainのcloneから`mise dot apply`を追加確認なしで実行する。本人によるmerge後に作業を再開した場合も、適用済みか確認し、必要なら実行する。Git操作の許可範囲は`git-policy.md`に従い、ホームへの適用許可を公開側のcommit・merge・pushの許可に広げない。

dotfilesのコードを端末のあるべき状態として扱う。miseによる設定反映は影響が本人の環境に限られるため、Coding Agentsによる実行を恒常的に許可する。Terraform apply・デプロイは適用対象と影響範囲が異なり、それらの禁止は解除しない。

適用前に`mise dot status`・`mise dot diff`・`mise dot apply --dry-run`で配置先、変更内容、起動されるhookを確認する。新規配置と、mainの変更に対応する管理対象の更新を適用する。ホームへの書き込みはサンドボックス外で実行する。削除・管理対象外の既存ファイルの置換・ユーザー編集との競合・適用エラーがあれば、`--force`や`--prune`を使わず停止し、`manual-operations.md`に従う。

適用後は`mise dot status`と`mise run agents:check`を実行し、共通資料・スキル・判定処理の欠落、配置定義と異なるリンク先、旧リンクの残存を確認する。ツール固有の入口は、配置定義と実際の参照先を別途照合する。mainへの取り込み、dry-runの成功、検査成功だけで適用済みと報告しない。

## 個人用の改善に着手する時間帯
- 通常モード・`local`モードを含む`todo`スキルの実行と、それに伴うタスク操作、勤怠保存、外部情報の同期、計画、日次ノート更新は定常フローとして対象外とする。チーム作業、業務用のバックログに関連する業務、業務上必要な勤怠ペースの確認・打刻取得も対象外とする。
- 対象は、個人用の運用やツールの改善・整備（`todo`スキル、個人用スキル、AGENTS.md、dotfiles、`tasks`コマンド本体など）とする。
- 対象時間は日本時間の平日10:00以上12:00未満、および13:00以上18:00未満とする。昼休みの12:00以上13:00未満は対象外とする。
- 対象時間内の依頼は着手せず、Obsidian vaultの`inbox.md`に`- [ ]`形式のアイデアメモだけを追記し、業務への集中を促す文面を返す。
- `write-plan`スキルに沿った業務用plan fileの作成・修正と、非公開の保存先へのコミット・PRは、業務上必要なplanフローとして対象外とする。
- `.codex/config.toml`の未コミット差分がモデル設定だけの場合は、時間帯にかかわらずただちにコミットしてよい。ほかの設定変更を含む場合はこの例外を適用しない。
- 共通指示・スキル・hookの呼称と配置は、`write-agent-instructions`の判断手順に従う。
