# 本人への操作依頼

## 依頼前の検証提示

Gitのcommit・merge・pushを含め、本人へ操作を依頼する場合は毎回適用する。検査結果やコミットメッセージ案だけを報告する場合も適用し、依頼文の有無で省略しない。禁止規則やhook拒否が発生した場合だけの手順にしない。

- 許可された確認・準備を先に実行し、依頼より前のチャット本文に、作業ディレクトリの絶対パス、対象リポジトリ・worktree、実行したコマンドの引数・対象、終了コードと実際の結果をコードブロックで示す。追加・変更した環境変数も、実際に実行した`env KEY=value ...`などの形で値を含めて示す。「必要な値を指定した」だけで済ませず、実行済みの確認コマンドを省略しない。
- 検証は変更対象のworktreeで行い、mainや別worktreeの結果で代用しない。実行前に`git rev-parse --show-toplevel`と`git branch --show-current`で対象を確認し、実行ツールにもその作業ディレクトリを明示する。結果のコードブロックには実際のcwdとブランチを併記する。
- コマンドごとに標準出力・標準エラーを省略せず示す。失敗後に成功した場合も、失敗した試行と再実行を両方示す。出力がなければ「出力なし」と記す。秘密情報だけを伏せ、その箇所を明記する。
- 成否に加え、テストの成功・失敗件数、警告、skip、未確認の範囲を示す。「検査済み」「すべて成功」だけの要約や、ツール出力・ログへの参照だけで済ませない。本人操作への引き継ぎを残した報告にも適用し、依頼文を省いて検証提示を省略しない。
- 本人に依頼する未実行の操作は、実行済みの検証と分け、その後に示す。Git操作の依頼方法は`git-policy.md`に従う。本人の完了報告後はCoding Agentsが結果を確認する。
- 送信前に、対象作業で実行した各確認のツール出力と本文を照合する。初回失敗・再実行、環境変数、標準出力・標準エラー、終了コードがそろっていなければ補ってから送る。簡潔さのために確認記録を成功の要約へ置き換えない。

## 禁止規則・hook拒否への対応

- 禁止規則・hook拒否は操作ごとに切り分ける。**実行・ファイルへの書き込み・チャットでの表示を区別し、書き込みの拒否だけを理由に変更案も表示できないと扱わない。手動編集を依頼するときは、対象ファイルの絶対パスと、編集位置が分かる差分または変更前後をチャット本文に示す。コマンドだけの提示や、ツール出力への参照だけで済ませない。秘密情報は伏せる。** 本人操作が必要な部分だけを未実行と明記して別のコードブロックで依頼する。Coding Agentsから確認できない場合だけ、理由を添えて本人に確認を依頼する。手動依頼の詳細は`troubleshoot-environment`を参照する。

## AWS CLIの手動実行

- コマンドを提示する前に、Coding Agentsから読める環境で`mktemp -d /tmp/command-evidence.XXXXXXXX`を使い、試行専用ディレクトリを確保する。返された絶対パスを会話で保持し、提示するコマンド内にも具体値で埋め込む。再試行には別ディレクトリを使い、ログをGitへ登録・上書き・削除しない。
- 対象アカウント・profile・region・操作内容と影響を確認し、実行するコマンド、cwd、実行条件を`command.txt`に記録する。認証情報の値は記録しない。AWS CLIに汎用のログ保存オプションがあると仮定せず、標準出力と標準エラーを画面にも保存する。TTYが不要なら`stdout.log`と`stderr.log`へ`tee`で分けて保存し、TTYが必要なら端末接続を保つPTY記録を使って`session.log`へ保存する。
- 本人向けのコピー可能なシェルブロックには`umask 077`、`set -o noclobber`、明示的なcwdへの移動、`AWS_PAGER='' AWS_CLI_AUTO_PROMPT=off`と`--no-cli-pager --no-cli-auto-prompt`を含める。TTYが不要な場合、標準出力と標準エラーは`> >(tee "$stdout_log") 2> >(tee "$stderr_log" >&2)`の形で保存・表示する。TTYが必要な場合は`script -qefc '<command>' "$session_log"`の形でPTYを割り当てて記録する。いずれもサブシェル内で実行し、コマンドの終了コードを`exit-code.txt`へ保存する。`script -e`で子コマンドの終了コードを返し、認証プロンプトと出力を端末へ表示する。Coding Agentsの`exec_command`では実行しない。`--debug`は必要な場合だけ付ける。
- 保存先の絶対パスと、完了後は「実行した」と返すだけでよいことを伝える。返答後はCoding Agentsが`command.txt`・選択したログファイル・`exit-code.txt`を読み、終了コードと出力から結果を確認する。秘密情報を返す操作では原本を全文表示せず、必要なメタデータだけを抽出する。共有用のマスキングは別ファイルで行う。ファイルの欠落・権限エラー・未完了を成功とみなさず、保存先や実行状況だけを確認する。結果の貼り付けは求めない。
