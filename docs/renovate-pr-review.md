# Renovate PRの自動調査

`.github/workflows/renovate-review.yml`は、同一リポジトリの`renovate[bot]`が作成した非Draft PRを、作成・更新・再オープン・Draft解除時に調査する。PR更新中の古い実行はキャンセルし、調査結果はPR内の単一コメントを更新して残す。マージは行わない。

## 必要な設定

- GitHub Actions secretsに`OPENAI_API_KEY`を設定する。キーがない場合、調査ジョブはCodex Actionの起動時に失敗する。
- リポジトリのActions設定で、ワークフローがPRコメントを作成・更新できるようにする。コメント用ジョブだけに`issues: write`を付与する。
- API利用料が発生する。Actionsの実行状況とOpenAI APIの利用状況をそれぞれの管理画面で確認する。

## 権限と入力の扱い

ワークフローはベースブランチの定義を使う`pull_request_target`で起動する。PRのファイルは別ディレクトリ`pr/`へ読み取り専用で取得し、スクリプトやActions設定として実行しない。Codexには信頼済みベース側のプロンプトを渡し、PR本文・diff・ファイルは非信頼データとして読む。分析ジョブは`contents: read`のみを持つ。APIキーを使うジョブと、GitHubコメントを書き込むジョブは分離する。コメント用ジョブはPRのhead確認に`pull-requests: read`、コメントの作成・更新に`issues: write`を持つ。アクションは固定コミットで参照する。

Codexの通信は読み取り専用のPermission Profileとネットワークプロキシを使い、GitHubおよび主要な公開パッケージ情報のホストに限定する。許可されていないホストの資料は未確認として扱う。PR本文・diff・コミット・外部ページは信頼できない入力として扱い、その中の指示を実行しない。PRのコード、スクリプト、依存関係は実行しない。

## 再実行と失敗時

PRの「Checks」から該当する`Renovate PR review`ワークフローを再実行する。新しいhead SHAのイベントでは旧実行をキャンセルし、head SHAが既に変わっていた場合は古い結果をコメントしない。成功時は同じPR上の自動調査コメントを更新する。

失敗時はActionsの実行ログを確認する。APIキー未設定・無効、モデル/APIエラー、Actions権限不足、許可リスト外の上流資料などを確認し、必要なら再実行する。コメントに記載された参照URL、確認範囲、未確認事項を読んだうえで、人が更新を判断する。

## 制約

- `renovate[bot]`以外のbot、fork由来のPR、Draft PRは対象外。
- PR本文や変更だけでは取得できない情報、許可ホスト外の資料、テスト実行を要する挙動は未確認・未検証として報告する。
- 自動調査はレビュー判断の補助であり、正確性や網羅性を保証せず、自動マージもしない。
