# 過去問の原文を保持する

## 目的

試験本来の難しさとひっかけを保つ。カードは原問題を再現して復習するものであり、LLMが書き直した問題ではない。

## 変更しないフィールド

`Question`の原文部分、空でない全`OptionN`、`OfficialAnswer`、`OfficialExplanation`は原本からそのままコピーする。読みやすくするために見える文言を変えない。作業記録にはUTF-8の原文を保存し、全角空白と改行も保つ。

個人情報保護士では、`Question`先頭の番号だけを`問題<N>. `に正規化し、末尾に空行一つと`第81回`などの回数行を追加する。これ以外に原本フィールドを変更しない。別回の同文問題をAnkiが重複扱いすることを防ぐためである。

Ankiフィールドへ入れる直前に、`&`・`<`・`>`の順でHTMLエスケープする。表示だけの変換とし、作業記録の原文は変更しない。

禁止する例

- 法令の条件語を簡単な同義語へ変える。
- 最も適切なもの・誤っているものという指定を落とす。
- 明示的な許可なしに、誤字に見える箇所を直す。
- 長い誤答選択肢を短縮する。
- 選択肢のラベルや順序を変える。
- 正規化した問題番号を`Question`から外し、`Source`だけに置く。
- 否定問題を肯定問題へ変える。
- 解説の重要そうな部分だけを抜き出す。
- 公式解説にLLM作成の理由を追加する。

## 抽出と照合

1. 問題と解答・解説を抽出する。
2. テキスト層がないか抽出できなければ、ページを画像化して見える文言を文字起こしする。カードを画像へ置き換えず、成果物はテキストにする。
3. 解析が崩れているか曖昧なら、文字起こしとページ画像を比較する。
4. 選択肢の順序を確認する。
5. 公式解答を確認する。
6. 解説の始点と終点を確認する。
7. 読めない文字が残ればそのカードの出力を止め、読める範囲の下書きを提示する。原本パス、PDFページ、異なる場合の印刷ページ、対象フィールド、記録識別子を付ける。`NeedsReview=true`にし、訂正か鮮明な資料を求める。訂正をページと照合できるまで元の下書きを保持し、受領前に完成扱いにしない。欠落を作り足さない。

## 選択肢の表示

付属テンプレートは表面に空でない選択肢をすべて表示し、学習者が頭の中で答えてから裏面を開く。JavaScriptボタン、`pycmd`、クライアント側の状態保存は、Ankiの各クライアントで一貫して動かないため必須にしない。

裏面では`OfficialAnswer`と`OfficialExplanation`を毎回、原文のまま表示する。問題と選択肢から分離して保持する。

## 派生メタデータ

原文として表示しない`Topic`・`Priority`・`Tags`・`CorrectOptionIndex`はLLMで付けられる。`CorrectOptionIndex`は公式解答に対応する原本選択肢の1始まり整数にする。対応が一意でなければ`NeedsReview=true`にする。

## 補助カード

原文の過去問復習が目的なら、想起・区別用の補助カードを既定では作らない。依頼があるか修復で必要な場合も、元の選択問題は変更せず、`generated`タグ付きの別カードを作る。生成文が試験に由来するとは説明しない。
