# デッキ作成の入力と実行環境

## 必要な環境

PDFを処理する前に、次を確認する。

- Popplerの`pdftotext`・`pdftoppm`・`pdfinfo`。Ubuntu・WSLでは`poppler-utils`に含まれる。
- JSON検証とCSV生成に使う`jq`。
- 原本の版を追跡する`sha256sum`と、一時作業領域を作る`mktemp`。
- スキャン画像を読む`view_image`と、画像認識に対応した実行中のモデル。

`command -v pdftotext pdftoppm pdfinfo jq sha256sum mktemp`で確認する。不足があれば、不足するコマンドと導入パッケージを報告して停止する。画像だけのカードへ切り替えたり、画像確認なしに文字を推測したりしない。`view_image`がなければ、ページ画像かテキスト層付きPDFを求める。Tesseractと日本語OCR辞書は必須ではない。Anki Desktopは出力したデッキの取り込みと確認に使う。


## モードと入力

1. 作成: 問題原本と公式解答・解説原本からデッキを作る。試験日や残日数が分かれば範囲の判断に使う。
2. 修復: コピーしたカード、画面画像、出力行、カードと失敗状況などを受け取る。例として、同じカードでAgainを繰り返す場合を扱う。

### JSONディレクトリ

文字起こし済みのJSONがある場合は、PDFの代わりにその絶対ディレクトリを受け取れる。変換前に[JSON入力手順](json-directory-input.md)を読む。

- 指定ディレクトリ直下の`*.json`だけを自然順で列挙する。
- `type: "normal"`と`type: "bundle"`に対応する。bundleの小問は一問ずつ展開する。
- 原文の選択肢ラベル、句読点、空白、改行は正規化しない。個人情報保護士の`Question`だけ、先頭の問題番号を正規化し、末尾に回数行を追加する。
- JSONのパスとSHA-256を`Source`に記録する。JSONにないPDFパスやページ番号を作らない。
- 個人情報保護士のタグは`第<回>回個人情報保護士`にする。明示された課題だけ`課題I`・`課題II`を追加し、内容から推測しない。入力中のその他のタグは使わない。
- `Question`の末尾には空行一つと`第<回>`を付け、同じ問題文が別回で再出題されても区別できるようにする。
- 最終CSVは、別途指定がなければJSONと同じディレクトリへ`第<回>回個人情報保護士_<YYYYMMDD>.csv`として保存する。日付不明なら日付部分を省き、その旨を報告する。中間ファイルは一時作業領域に置く。

PDF入力で問題または解答・解説原本が不足している場合は、全体の作成前に不足資料を求める。部分出力はユーザーが受け入れた場合だけ行う。未解決の記録を通常の学習デッキへ混ぜず、原本ファイルとページで報告する。`NeedsReview=true`のまま通常出力しない。JSON入力では各ファイルに必要な問題と解説情報が必要になる。

個人情報保護士以外の試験に四択の形式を自動適用しない。原文保持の原則は維持し、列順と選択肢数を確認する。PDF抽出前に[抽出手順](extraction-workflow.md)を読み、問題ごとの状態と下書き確認の条件に従う。
