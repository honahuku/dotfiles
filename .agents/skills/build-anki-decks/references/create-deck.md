# 過去問の原文を保持したAnkiデッキの作成

原本からデッキを作る場合は、先に[入力と実行環境](deck-input-and-environment.md)を確認する。

## 原文保持の最優先規則

実在する過去問の文言は変更しない。`verbatim_mcq`では次を守る。

- 問題文は、許可された問題番号の正規化後に原文をコピーする。先頭はASCII数字の`問題<N>. `に統一する。`問題 28. `・`問題２８．`・`問題28。`は`問題28. `になる。自作の通し番号や`Source`だけに置き換えない。
- 個人情報保護士では、問題文の後に空行一つと`第<回>`を付ける。
- すべての選択肢、ラベル、句読点、条件、否定、特殊な表現、ひっかけをそのままコピーする。
- 公式解答と公式解説も原文どおりにし、出題順を保持する。
- 短縮、要約、明確化、表記統一、訂正、現代化、言い換えをしない。誤字や不自然な文も黙って直さない。
- 誤答選択肢を分かりやすく間違った文へ変えない。問題文と選択肢にLLM作成のヒントを加えない。

見える文言を変えないHTMLエスケープや改行の表示だけは許可する。過去問に表示できるLLM作成文は、中立的なUI文言だけである。

スキャンや依存ツールの問題で文字抽出できない場合も、[抽出手順](extraction-workflow.md)に沿ってページを画像化し、`view_image`で開いて文字起こしする。最終回答とCSVはテキストで出力し、画像だけのカードや日本語OCR辞書の導入を必須にしない。読めない文字や範囲があれば、そのカードの出力を止め、原本パス・ページ付きの所定の下書きを示す。`NeedsReview=true`とし、ユーザーの訂正まで完成扱いにしない。


## 作成手順

### 1. 問題と公式解答・解説を対応付ける

JSON入力は[JSON入力手順](json-directory-input.md)で展開し、PDF抽出を省く。ただし原本追跡、解答番号の検証、問題の重複確認、`status: "ready"`の条件は同じである。

問題ごとの作業記録に次を保持する。

- 問題原本と解答原本のパス・SHA-256。
- PDFページ、異なる場合の印刷ページ、原本上の問題識別子。
- 問題文、順序を保った選択肢、公式解答、公式解説、参照ページ、分野。
- 抽出確度`high`・`medium`・`low`。
- 状態`extracted`・`draft`・`confirmed`・`ready`・`blocked`。

抽出コマンド、ツールの版、ページ、[抽出手順](extraction-workflow.md)にある五つの原本照合も記録する。確度が`low`、または解答との対応が不確実なら`NeedsReview=true`にする。読めてもページ構造や解答境界の確認が必要なら`medium`とする。全検査に通り、`NeedsReview=false`の記録だけを`ready`にする。

出力前に各問を原本と照合する。画像中心のPDFや崩れた抽出結果を信頼せず、スキャンではページごと・問題ごとに日本語、否定、条件、句読点、選択肢ラベル、行の境界を確認する。OCRやライブラリの失敗を理由に、文字の代わりにページ画像だけを返さない。訂正が必要なら所定の下書き形式を使う。

### 2. 過去問は原文保持の選択問題にする

既定は`verbatim_mcq`とする。[原文保持の規則](verbatim-mcq.md)と[出力形式](output-schema.md)を読む。問題、全選択肢、公式解答、公式解説をそのまま使い、キーワード抽出、解説要約、事例の規則化、別問題への置き換えをしない。

表面には原文の問題と全選択肢を表示し、学習者が頭の中で回答してから裏面の公式解答・解説を開く。元の問題の代わりを自動生成しない。

### 3. 穴埋めカードを混ぜない

このスキルは原文保持の過去問を扱う。派生した穴埋め知識カードは`build-anki-cloze-decks`で作る。

### 4. 残日数から収録範囲を決める

[試験日と収録範囲](exam-strategy.md)を読み、収録する試験回数や派生カードの範囲を決める。目標枚数に合わせるために、問題を削除・書き換えしない。

### 5. 品質を確認する

- `Question`の先頭が`問題<N>. `である。
- 個人情報保護士では、末尾の独立した`第<回>`行と試験タグが一致する。
- 出力内の見える`Question`全文が一意である。重複なら安定した識別方法を決めるまで止める。
- 選択肢の数・順序が原本と一致し、欠落がない。
- 否定や条件が落ちていない。
- 公式解答・公式解説が各原本に一致し、言い換えがない。
- 原本へ追跡でき、`CorrectOptionIndex`と公式解答が一致する。

`CorrectOptionIndex`は解答対応を確認する技術的なメタデータであり、公式解答文の代わりにしない。個人情報保護士の原本に五つ以上の選択肢があれば、削らず出力前に確認する。

### 6. 出力する

[出力形式](output-schema.md)からCSVを直接生成し、`ready`だけを出力する。JSONの作業記録は[抽出手順](extraction-workflow.md)の検証と`jq @csv`を使い、カンマ、引用符、改行を正しくエスケープする。通常のヘッダー行はカードとして取り込まれるため、`#columns:`・`#tags column:`のAnkiファイルヘッダーを使う。

空行が必要なフィールドには実際の改行文字を入れ、文字列の`\n`で代用しない。改行を含むフィールドを引用符で囲み、CSVを再読込して同じフィールド内に残っていることを確認する。

JSON入力は全ファイルを一時領域の一つの記録配列へ展開・正規化してから検証する。不正または未解決の入力があれば、明示的に部分出力を受け入れられるまで一部だけを出力しない。個人情報保護士の試験回数を原本ファイル名、入力ディレクトリ、明示入力から一意に決められなければ確認する。

PDF入力の既定名は問題PDFから決める。`第80回 個人情報保護士認定試験・問題_20250921.pdf`なら`第80回個人情報保護士_20250921.csv`にする。空白と説明的な試験名の接尾辞を除き、回数と日付を残す。関連出力も同じ基本名にし、複数ファイルが必要な場合だけ用途の接尾辞を付ける。

明示的に依頼された想起・区別用の派生カードは、[出力形式](output-schema.md)の派生カード形式で別CSVにする。処理した原本問題数、原文保持カード数、派生カード数、`needs_review`数、残日数に応じた方針も報告する。必要に応じて付属の表面・裏面HTMLとCSSを、一度だけ行うノートタイプ設定用に渡す。毎回の回答後に公式解説を表示する。


## 対話と取り込み

不足する原本、出力形式の判断、明示した下書きの訂正だけを質問する。大量の行をチャットに並べずファイルを渡す。原本が不自然でも保持し、一般知識で欠落を黙って補わない。日々の復習はAnkiで行う。

取り込み用CSVを出力するときは、[CSVとノートタイプの取り込み条件](deck-import-requirements.md)を読む。
