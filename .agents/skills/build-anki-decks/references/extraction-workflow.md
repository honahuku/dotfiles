# 原本の抽出手順

原本ごとに次の順で進める。一つのツールのエラーメッセージだけで抽出方法を決めない。

## 原本と作業領域

各原本を絶対パスにし、問題原本と解答・解説原本を別の入力として保持する。`mktemp -d /tmp/build-anki-decks.XXXXXX`で専用の一時領域を作り、完了までファイルを保持する。全問題記録に原本パスと`sha256sum`を残し、安定した`record_id`を`<source-sha256>:<pdf-page>:<question-identifier>`から作る。

## テキスト層の抽出

各PDFのページ数とメタデータを`pdfinfo <absolute-pdf-path>`で確認する。抽出には`pdftotext -layout <absolute-pdf-path> <work-area>/source.txt`を使う。問題境界、選択肢順序、解答・解説境界を原本と照合するまでは下書きである。終了コード0だけで、日本語が正しく取れたとはみなさない。

`pdfinfo`の出力、`pdftotext -v`の出力、実行コマンド、対象ページ範囲を記録する。抽出が非0終了か`test -s <work-area>/source.txt`が失敗したら、直ちにページ画像化へ進む。抽出文と画像は作業領域に残す。

全ページについて空でない文、問題番号、選択肢ラベル、解答・解説境界を調べる。一つでも失敗したページは画像化する。安定した目印がない形式なら、正しく抽出できたページを推測せず全ページを画像化する。

## スキャン・曖昧なページの画像化

画像確認が必要なページだけを処理し、`pdftoppm -v`を記録する。ページNには次を使う。

```text
pdftoppm -r 300 -f N -l N -png -singlefile <absolute-pdf-path> <work-area>/page-N
```

PNGを`view_image`で元の解像度で開き、実行中の画像対応モデルで文字起こしする。別のOCRモデルや日本語OCR辞書は必須にしない。導入済みのローカルOCRは比較用にだけ使え、正解の根拠にはしない。ツールの版、コマンド、DPI、ページ番号を記録する。

見える日本語、文字、句読点、否定、条件、選択肢ラベル、順序、全角空白、改行を保持する。文字起こしをページ画像で置き換えない。

記録ごとに`question_checked`、`options_checked`、`official_answer_checked`、`official_explanation_checked`、`source_location_checked`を別々に保持する。画像またはテキスト原本との全五項目の照合が通った場合だけ確度を`high`にする。文字は読めるが構造確認が残る場合は`medium`、文字や解答対応が不確実なら`low`にする。

## 不確実な箇所の下書き確認

状態は次のいずれかにする。

- `extracted`: 文字は得られたが原本照合が未完了。
- `draft`: 画像の文字起こしに読めない箇所や不確実な範囲がある。
- `confirmed`: ユーザーが下書きを承認・訂正した。
- `ready`: 原本照合、解答対応、メタデータ、形式検証が通り、`NeedsReview=false`である。
- `blocked`: 必須の原本またはページが利用できない。

遷移は`extracted -> confirmed -> ready`、`extracted -> draft -> confirmed -> ready`、または必須原本がない場合に`ready`以外から`blocked`とする。`confirmed -> ready`には全五項目の照合、一意な解答対応、`NeedsReview=false`、形式検証が必要である。`ready`からは遷移せず、訂正時は新しい下書き状態を作る。

`draft`はその記録の出力を止め、次の情報を必ず示す。

```text
原本ファイル: <絶対パス>
ページ: <ページ番号>
フィールド: <Question|Option1|...|OfficialExplanation>
下書き:
<読めた範囲の文字起こし>
不明箇所:
<文字・範囲・位置>
```

訂正を求め、受け取った文をそのまま適用して画像と再照合する。`confirmed`だけが`ready`へ進める。不確実性と解答対応が解決するまで`NeedsReview=true`を保つ。訂正は画像照合が通るまで別の`user_correction`に保存し、作業領域に訂正履歴を残さず元の下書きを上書きしない。

## 解答と解説の対応付け

問題識別子、または問題・解答それぞれの原本ファイル、PDFページ、印刷ページ、問題番号で対応付ける。印刷ページがPDFページと違えば両方を別フィールドにする。公式解答文と解説境界を解答原本で確認する。原本の順序が異なる場合、行の位置だけで対応付けない。

`CorrectOptionIndex`へ変換できる形式は、数字`1`〜`4`、ラベル`A`〜`D`、`ア`〜`エ`、一から四の丸囲み数字、または一つの選択肢への完全一致に限る。`第三肢`などの漢数字・序数、部分一致、その他の形式を推測で変換しない。未対応または一意でなければ`draft`・`blocked`にして訂正を求める。

## 完成した記録だけを出力する

`draft`・`extracted`・`blocked`や`NeedsReview=true`を通常学習用に出さない。部分出力は明示的に受け入れられた場合だけ行い、除外した記録を原本ファイルとページで報告する。確認用の不確実性ファイルを明示依頼された場合は、学習デッキと分けて用途を明記する。

確認済み記録をJSON配列で保持し、CSV生成には`jq @csv`を使う。保存前に必須フィールドと許容値、Ankiヘッダーの完全一致、ヘッダー後のデータ行数と出力記録数を照合し、取り込み前にAnkiのプレビューを確認する。
