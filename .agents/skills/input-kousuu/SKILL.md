# 確認済みの活動と勤怠から、対象期間の工数を分類して入力用の表を作る

対象: $ARGUMENTS

最初に保存先・分類基準・権限・手順を確認する。不明な組織固有の値は推測せず、ユーザーに確認してから進める。

シートを使う場合は、集計・修正の直前に日付見出し、勤務時間、プロジェクト行を読み直す。日付と列の対応を明示的に照合し、列位置や前回の値だけで勤務時間を割り当てない。入力用の表はシートのプロジェクト行と同じ順序にし、コード順や固定の一覧で並べ替えない。シートにない必要なコードは既存行の後に置き、追加が必要なことを示す。

各日の分類合計と、同じ日付の勤務時間との差分をツールで計算し、すべて0であることを確認してから保存する。修正後も再計算し、既存の入力値との差分と勤務時間との差分を区別する。

活動の実績と予定を区別し、会議は出席を確認できた分だけ計上する。分類ごとの時間を保持し、日ごとの配分は入力先で正と定められた勤務時間に合わせる。活動記録や手元の勤怠ログでその値を補完・上書きせず、対象日も入力先の基準に従う。数値計算はツールで行い、未分類・低確度の項目は確認する。入力案と外部システムへの書き込みは分けて扱う。

## 保存先タスクの決定

- 保存先には、対象期間に対応する open タスクだけを使う。具体的なタスク名や期間の判定条件は、利用環境の補足に従う。done・アーカイブ済みのタスクは候補に含めない。
- 有効な候補が複数ある場合は、どれを使うかユーザーに確認する。該当する open タスクがない場合は、新しいタスクを登録するか確認する。
- ユーザーが登録すると明示した場合に限り、既存の `register` スキルでタスクを登録し、返された ID を保存先にする。登録の分類や属性は `register` の定義に従い、このスキルで重複して実装しない。
- 登録しない回答または未回答の場合は、新規登録もタスク詳細への記入も行わず、保存できなかったことを伝える。done・アーカイブ済みタスクを代わりに使わない。
