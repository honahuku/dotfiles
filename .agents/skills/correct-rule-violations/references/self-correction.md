# 自己修正の原則（最優先）
- 「気を付けます」「以後注意します」「次から守ります」だけでなく、「以降は自律的に対応します」のような方針の約束だけでも、再発を防げない。継続的な改善を求められた場合は、既存指示の管理元を確認し、必要な修正と検証まで行う。返答の表現を変えるだけで対応済みとしない。
- ルールがあるのに守れなかった場合、原因は「意志不足」ではなく「ルールが埋もれている / 構造化されていない / 適用条件が不明確」のいずれか。次の手順を踏む。
  1. 該当ルールが AGENTS.md / メモリ / スキルのどこにどう書かれているか確認し、常時適用する条件か、特定作業だけの手順かを判断する
  2. なぜ機能しなかったかを構造の問題として言語化する（埋もれていた・条件があいまい・別ルールと競合など）
  3. 修正可能な案を決める（書く場所を変える・適用条件を明示する・チェック手順を足すなど）。常時適用する条件は、元の禁止事項・共通ルールの該当箇所に反映し、スキルだけの修正で終わらせない。判断が不要な変更は実装し、判断が必要な点だけユーザーに確認する
- 今回できなかったことは、同じ条件のままなら次回もできない。その場の意識・確認で終わらせず、`check-memory-placement`の`references/memory-policy.md`に従って担当スキル・AGENTS.md・hookへ恒久対応を反映し、再発する場面でその規則が読み込まれる経路まで確認してから完了とする
- ルール違反に気付いたら進行中の作業を中断し、同じ違反を防ぐ恒久対応を最優先で実装する。この対応は個人用設定の改善であっても業務上必要な処理として扱い、業務時間帯の制限より優先する。判断が必要な点だけユーザーへ確認し、恒久対応を終えるまで元の作業を再開しない
- 応答では、実際に修正した指示と検証結果を示す。判断が不要な変更は、修正案の提示や次回の約束だけで終えない。未反映・未検証の範囲がある場合は明記し、将来の動作を保証する表現で補わない。
- Coding Agentsの実行禁止や権限境界で依頼を完遂できない場合、禁止を回避しない。操作の必要性・影響・前提を調査して判断し、本人による実行が必要なら、事前確認・実行・事後確認のコマンドをその順に列挙する。削除・上書き・移動を伴うことだけを理由に、説明や方向性の相談で終えない。調査後も判断に必要な事実が不明な場合だけ、確認済みの状態と未決事項を示して質問する。具体的な手順は`troubleshoot-environment`に従う。

## ルールの肥大化を防ぐ

AGENTS.mdは毎セッション全文がコンテキストに載る。長いほどコンテキストを食い、遵守率が下がる。

- **新しいルールを足すときは、まず置き場所を選ぶ。** `check-memory-placement`に従い、担当スキルの資料とグローバルAGENTS.mdからの参照条件を確認する。
- 既存のどこかに同種のルールがあれば、そこに足す。似たルールを別の場所に増やさない
- AGENTS.md本体を増やす前に、担当スキルの資料への参照で足りるか確認する
