# コード作成とコマンド実行の制約

## シェルスクリプトとシェルコマンド

シェルスクリプトおよびシェル構文を含むコマンドは、[Google Shell Style Guide](https://google.github.io/styleguide/shellguide.html)に沿って読みやすく書き、[ShellCheck](https://www.shellcheck.net/)の指摘を解消する。単発コマンドでも、実行対象・実行条件・副作用が明確で、失敗時に意図しない後続処理が動かない形にする。

- `A && B`はAが成功したときだけBを実行し、`A || B`はAが0以外で終了したときBを実行する。終了ステータスが「該当なし」などの通常状態を表す場合もあるため、状態を区別する分岐は`if`で明示する。
- `A && B || C`を`if`・`else`の代わりに使わない。[ShellCheck SC2015](https://www.shellcheck.net/wiki/SC2015)のとおり、CはAまたはBの失敗時に実行される。
- ファイル名の検索に`ls`の出力を`grep`で解析しない。[ShellCheck SC2010](https://www.shellcheck.net/wiki/SC2010)に従い、globまたはループを使う。
- 状態を変えるコマンドは、対象と実行条件を明示し、対象範囲と副作用を先に確認する。連結や条件分岐で、失敗時に後続の変更処理が意図せず実行されないようにする。

## 発火条件の注釈

このスキルの適用だけで、依頼範囲を超えたコード作成・実行が許可されるわけではない。新規・既存を問わず、実行前に内容・入力・対象・副作用を確認し、`check-command-policy`の可逆性判断に従う。復旧可能な依頼範囲内の作業は進め、不可逆または影響が不確実な操作だけ具体的な対象と影響を示して許可を得る。


## コマンドの実行直前

読み取り、検索、lint、fmt、検証のコマンドを実行する前に、[コマンドと出力](../../check-command-policy/references/command-policy.md#コマンドと出力)を適用する。該当するツール・操作の条件も、`check-command-policy`の指示に沿って見出し名とMarkdownリンクで特定して参照する。

片付け・競合解消・設定移行で既存のファイルやリンクを移動する場合は、目的と復旧可能性を確認する。依頼のない独自の退避先は作らない。削除・移動は操作名だけで拒否せず、`check-command-policy`の可逆性判断に従う。

削除の復旧可能性は、実行環境のalias・関数や管理ツールを確認して判断する。不可逆または復旧が不確実な場合は対象・影響を示して明示許可を得る。許可後はCoding Agentsが実行し、事後確認を行う。本人操作が必要な場合は`troubleshoot-environment`の手動依頼手順に従う。
