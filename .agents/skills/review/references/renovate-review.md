# Renovateの検証と依存更新のレビュー

## ローカル実行のモードを決め、結果を報告する

- ローカル実行の依頼で`--dry-run=`の指定がなければ、同じHEAD・対象範囲に対して`--platform=local --dry-run=extract`、`--platform=local --dry-run=lookup`を別々に、この順で両方実行する。モードが明示された場合はその指定に従う。
- 実行結果には毎回、各実行で指定した`--platform=<値>`・`--dry-run=<値>`、実際の動作モード、対象HEAD・対象範囲、終了コード、確認できたことと未確認事項を示す。フォールバックがあれば、指定値と実際の動作を区別する。
- `extract`では依存抽出、`lookup`では更新候補・PRタイトルの生成までを確認し、GitHub上のPR更新を検証済みとしない。両方を実行してもPRの検証に不足する場合は、不足する情報と`full`で確認したい内容を示し、追加実行を提案する。実行は明示指示を待つ。
- `--platform=local`は`full`をサポートせず、指定しても`lookup`へフォールバックする。`full`相当の検証を提案するときは、対応するplatform・対象・副作用を確認した実行方法を示し、localで`full`の検証ができると説明しない。適用・デプロイなど共通ルールの禁止操作は実行しない。

参考：[Renovate公式ドキュメント：Local](https://docs.renovatebot.com/modules/platform/local/)。localのツール既定値は`lookup`のため、依頼時のモード指定を省略しない。

## 上流の変更を確認する

- PR本文のRelease NotesとCompare Sourceは、リンク先の本文を読む。Bundleなどに列挙された各コンポーネントのChartとAppも、それぞれ確認する。利用環境で無効なコンポーネントも、列挙された版の要約から省かない。
- 更新前から更新後までの間に公開された各バージョンの主な変更を追う。Chartのノートが製品説明だけの場合は、AppのリリースノートとChartの比較差分で変更内容を補う。リンク切れや未公開の版は未確認として扱い、前後の版から内容を推測しない。
- リリースノートから参照された変更PR、移行ガイド、依存ライブラリの変更履歴のうち、破壊的変更の影響評価に必要な参照を追う。対象コンポーネント・対象版・利用基盤に関係する公式の非推奨・サポート終了・互換性・既知の問題のアナウンスも探し、対象バージョンと発効日を確認する。

## 今回の利用構成と照合する

- lockfileやChartの依存定義を比較し、今回変わる版と更新前から収録済みの版を分ける。リリースノートに列挙された全コンポーネントが、今回更新されるとはみなさない。
- 環境別の有効・無効設定、実際のAPI利用、実行基盤のバージョン、生成マニフェストの差分を、今回の互換性判断に必要な範囲で確認する。設定上の状態と実環境で確認した状態は区別する。
- 破壊的変更は、ライブラリ利用者向けのソースAPI変更、運用者向けの設定移行、実行時の挙動変更、サポート範囲の変更を分けて評価する。告知の存在だけで不具合とせず、利用するAPI・設定・基盤との関係から影響を判断する。パッチ更新やCI成功だけでも互換性を判断しない。
- 対応が必要な場合は、成立条件、影響、必要な移行・確認を示す。更新前から存在する制約は、今回初めて導入される問題と分ける。判断に必要な参照が読めない場合は、承認に不足する情報として残す。

## 結果に含めること

各バージョンの要約と、破壊的変更・アナウンスの確認結果を最終応答に含める。PR本文の転載は避け、調査で分かった内容と根拠を簡潔に示す。

| 項目 | 含める内容 |
| --- | --- |
| バージョン別の要約 | 対象コンポーネント、Chart / Appなどの版、主な変更、出典リンク。中間の公開版も区別し、同じ内容は重ねない |
| 今回の影響 | 実際に更新されるか、更新前から同じ版か、対象環境で有効か、利用者への影響 |
| 破壊的変更・アナウンス | 対象版・発効日、成立条件、今回への影響、必要な対処または確認、出典リンク |
| 未確認事項 | 読めなかった資料や取得していない実環境情報、そのため判断できない範囲 |

該当する告知が見つからなければ、確認した資料の範囲で見つからなかったと書く。未確認と影響なしを混ぜず、評価をapprove判断へ反映する。
