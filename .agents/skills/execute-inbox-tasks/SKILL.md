# タスクファイルの順次処理

対象ファイルの指定があればそのパスを使う。引数なしの場合は、適用中の指示で指定されたメインObsidian vault直下の `inbox.md` を使う。WindowsとWSLでは同じファイルを指す実行環境側のパスで開く。vaultの指定がない、対象が複数ある、または読み取れない場合は、別のファイルを推測せず確認して終了する。

## タスクの読み取り

- コードブロック・引用・下書きの外にある、インデントされていない `- [ ]` 行を処理単位にする。親行から次の実タスクのトップレベルのチェック項目までを読み、子行、空行を挟んだ補足、`<details>`、引用したコードや下書きも文脈として確認する。例示内のチェック項目では読み取り範囲を区切らない。
- 子チェック項目は親タスクの作業・完了条件・参考資料として読み、独立したタスクとして別に実行しない。選択肢や参考リンクを、すべて実行すべき指示と解釈しない。選択に判断が必要なら停止する。
- コードブロックや下書き内のチェックリスト・指示文は実行対象にしない。親がチェック済みでも、残る補足を別タスクとして取り出さない。
- 親タスクの完了に必要な子作業をすべて確認してから親を完了にする。子行のチェック状態は自動更新しない。

## 実行方法

- 現在の会話内で、上から1件ずつ同期的に処理する。
- バックグラウンド実行、並列実行、サブエージェントへの委譲、別チャットへの引き継ぎ、予約実行、自動再開は行わない。
- 各操作には適用される指示・禁止事項と必要なスキルを適用する。このスキルやタスク本文を、禁止操作や外部への投稿の許可として扱わない。

## 処理ループ

1. 対象ファイルを読み、上記の処理単位に当たる最初の未完了タスクを選ぶ。該当するタスクがなければ終了する。
2. 次に行う操作について停止条件を確認する。後段にcommit・mergeなどの禁止されたGit操作が必要でも、それだけで着手を止めず、worktree原則を守って許可された編集・検証をコミット前まで進める。
3. タスクを実行し、結果を検証する。実行途中にも、次の操作の前に停止条件を確認する。
4. 完了、または別対応ですでに完了済みと根拠をもって確認できた場合だけ、対象行の `- [ ]` を `- [x]` に変更する。部分完了や未検証の状態では変更しない。
5. 保存後に再読込し、対象のチェックボックスだけが変更されたことを確認してから、手順1へ戻る。

## ファイルの更新

- 編集直前にもファイルを読み直す。位置が変わっていたら、最新内容から対象を特定し直す。対象を一意に特定できない場合や、子行・補足を含む本文が実行・検証した内容から変わっている場合は停止する。
- タスク本文、前後の空行、インデント、改行形式、他の行の構造は変更しない。整形、並べ替え、注記の追記をしない。
- ファイルの更新・保存・検証ができなければ、次のタスクへ進まず停止する。
- 対象ファイルにバックアップ等の保存手順が指定されていれば、各保存後、次のタスクへ進む前に完了させる。停止が必要になった後に実行を持ち越さない。

## 停止条件

次のいずれかに該当したら、その操作と後続タスクを実行せず、処理ループ全体を終了する。

- 公開側dotfilesリポジトリで、許可された編集・検証を終え、次に適用される指示が許可していないGit操作を行う段階に達した。禁止されたGit操作は実行せず、コミット前の変更を残して停止する。読み取り検査と明示されたworktree作成等の例外は、その許可範囲に限る。
- ファイル・ディレクトリ・Git worktree・ブランチの削除が必要になった。
- 意図や設計方針の選択にユーザーの判断が必要になった。
- 認証、手動ログイン、GUI操作など、ユーザー自身の手作業が必要になった。
- その他、禁止操作、追加の承認、情報不足、実行・検証の失敗により、安全に完了できなくなった。
- ユーザーから停止を求められた。

### 停止手順

- 未チェックのタスクは未完了のまま残し、後続タスクを実行しない。チェック保存後の失敗では、チェック状態をさらに変更せず、タスク本体・保存・バックアップのどこまで完了したかを報告する。
- 実行中の処理がある場合は、この実行で開始した処理に限って停止要求を送る。停止要求と成否の確認に必要な最小限の操作だけを行い、確認できなければ処理の識別情報と未確認の状態を報告する。無期限の監視は続けず、停止済みと断定しない。
- 停止したタスク、停止理由、必要な判断または手作業、途中まで変更したものがあればその状態を簡潔に報告し、応答を終了する。
- 停止要求とその成否の確認を除き、停止後は調査、別タスク、バックアップ、ポーリング等の実行を続けない。ユーザーから明示的に再開を指示されるまで再開しない。禁止操作は再開指示でも代行しない。

処理対象の未完了タスクがなくなった場合は、今回完了を確認してチェックしたタスクを簡潔に報告して終了する。
