# 個人文脈を必要なときだけ使う

## 参照先

`~/.agents/docs/personal/context.md`の索引を確認し、必要なセクションだけを読む。健康・人間関係は`global/`、キャリア・研究は`research/`、集中時間は`planning/`、カレンダー判断は`sandbox/`のセクションを参照する。資料がなければ過去の状態を推測しない。

## 取り扱い

- 健康情報などの機微な内容は、判断に必要な範囲だけ使う。回答で不用意に列挙しない。
- 過去の状態を現在も続いている事実として扱わない。日付や現在の状態が重要なら確認する。
- 文章上の好みは、内容の正確さやユーザーの明示的な指示より優先しない。
- 新しい情報をCoding Agentsの自動生成メモリへ手作業で書かない。恒久的に残す必要がある場合は、更新先を提案して確認を取る。

## 新しくメモリを作成するトリガー

次のいずれかに当てはまるとき、非公開資料の該当セクションにメモリを追加する（メモリかスキルかの判断自体は`check-memory-placement`スキルを先に確認する）。

- ユーザーが自分の健康・体調・キャリア・人間関係・仕事の好みについて、今後のセッションでも踏まえてほしい情報を明示的に開示・依頼したとき
- 会話の中でユーザーの特性・傾向（癖・強み・弱み）が繰り返し話題になり、ユーザー自身がそれを継続的に踏まえてほしいと示したとき
- 特定の対人関係（上司・同僚・関係者）で、今後の相談・文面支援において慎重な配慮が必要だと分かったとき

**作成したら次を必ず行う。**

1. 対応する既存スキルを確認し、情報本体は非公開資料の適切なセクションへ保存する（`check-memory-placement`参照）。
2. 繰り返し使う個人情報も公開スキル本体やreferencesへ転記しない。公開側には非公開資料を読む条件と参照先だけを置く。
3. 転記先が無い場合は、関連するスキル（`todo`等の日次計画系、`apply-git-strategy`等）に一行、「この話題が出たら`use-personal-context`の該当ファイルを読む」という明示参照を追加する。`description`の自律発火だけに任せない。
