# シェル初期化とCLIのPATH確認

## ユーザーと同じシェル環境を使う

Coding Agentsでも、ユーザーが使うPATH・alias・関数を利用できることを前提とする。利用できない場合は、環境の不具合として原因を調べて修正する。見つからないコマンドの固定パス指定や別の導入版への置き換えだけで済ませない。過去の検証結果を現在の状態とみなさない。

`command not found`やユーザー環境との差がある場合は、次の順で確認する。

1. 実行シェル、ログイン・非ログイン、対話・非対話、初期化ファイルの管理元を確認する。Bashでは`.bash_profile`・`.bash_login`・`.profile`・`.bashrc`・`.bash_aliases`の実在と読み込み経路を調べる。
2. 初期化ファイルを読み、途中の`return`、対話シェル限定の条件、読み込みガードによって、必要なalias・関数の定義まで到達しない状態になっていないか確認する。ファイルが存在するだけで、読み込まれているとは判断しない。
3. 初期化に不備があれば管理元で修正する。ユーザーと共有するalias・関数と、対話時だけ必要なプロンプト・補完を区別し、非対話シェルでも必要な定義が使えるようにする。Bashのalias展開設定も確認する。制限を回避するためにシェルやインタプリタを起動しない。
4. 初期化を確認・修正しても見つからない場合に、同じ実行シェルで`type -a <command>`・`command -v <command>`を確認し、管理設定と照合する。`tasks`なら`type tasks`を使う。`which`の出力だけで、alias・関数も含めて存在しないと判断しない。
5. 修正後は新しく起動した実行環境で名前解決と必要な動作を確認する。worktreeだけの修正で、現在のホーム配下へ適用済みとは報告しない。本人操作が必要な場合は、確認済みの原因と反映・事後確認の手順を示す。

## aqua管理のCLI

- `uv`・`gh`など通常のコマンド名で起動する。PATHでaquaのbinへ解決されることは許可されている。起動リンクやパッケージ実体をパス指定で直接実行することは、手動手順の提示を含めて禁止する。
- 設定と実体を確認してから、バージョン確認へ進む。コマンド名が同じという理由だけで別の導入版へ切り替えず、その場のPATH前置で問題を隠さない。
- 設定の修正など本人操作が必要なら、`troubleshoot-environment`の手動依頼手順に従って止める。
