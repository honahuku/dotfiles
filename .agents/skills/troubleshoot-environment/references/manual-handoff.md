# 本人への操作依頼と実行結果の確認

## Coding Agentsが実行できない操作を手動依頼する

- Terraform・Kubernetes manifestの品質確認は`write-safe-code-and-scripts`のCI確認・停止条件を優先する。禁止CLIの必要な結果がCIから得られない場合、別手段や本人向けCLIコマンドを自動で代案にせず、確認済みのCI状態と不足する結果を示して判断を仰ぐ。
- リポジトリ規則などCoding Agentsの操作制限で依頼を完遂できず、本人が安全に実行できる場合は、制約の説明だけで終えず手動実行の手順を示す。情報取得・分析・保存だけでなく、編集・削除・コマンド実行も対象とする。
- 禁止規則やhook拒否の対象を操作ごとに切り分け、許可された確認・準備はCoding Agentsが先に実行する。`which`・`ls`・設定の読み取りなどを、後続に禁止操作があるという理由で本人へまとめて依頼しない。操作の理由、対象、変更内容・影響を確認し、未確認の状態から破壊的な操作を推測で提案しない。別ツール・ラッパー・サブエージェントでCoding Agentsの制限を迂回しない。
- 提示するコマンドには、共通AGENTS.mdのt-wadaのスタイルに従う`#`コメントを添える。特に設定ファイルの一時指定や実行順序の意図、通常の方法を採らない理由は、コマンドだけから読み取らせない。根拠のある前提・影響だけを書き、逐語的な説明を繰り返さない。
- 手動実行コマンドの出力は実行中に画面へ表示し、ログにも残す。TTYが不要なコマンドはBashの`> >(tee "$stdout_log") 2> >(tee "$stderr_log" >&2)`で標準出力・標準エラーを別々に保存する。TTYを必要とするコマンドでは、このリダイレクトにより子プロセスがTTYを検出できなくなることがあるため使わない。util-linuxの`script -qefc '<command>' "$session_log"`などPTYを維持する記録方法を使い、子プロセスの終了コードも保存する。ログだけへ出力し、実行中に画面で確認できない手順は提示しない。
- 手動依頼は、次の順に実行状態を分けて示す。確認済みか未実行かが曖昧な一括コマンドを渡すと、本人に不要な再確認をさせ、必要な操作を見失わせるため。
  1. Coding Agentsが実行済みの確認・準備：実行したコマンドと実際の結果をコードブロックで示す。本人への実行依頼ではないことを明記する。Coding Agentsと本人でシェルやPATHが異なる場合は、自分の結果を本人の環境の結果と混同しない。
  2. 本人操作（未実行）：禁止規則・hook拒否など本人操作が必要な理由と、対象・影響を説明する。コミットはlazygitを前提にworktreeの絶対パスと対象ファイルを自然文で依頼し、コミット用コマンドは示さない。Git操作の依頼と、それ以外のコピー可能なコマンドブロックを分け、連結しない。手動編集の差分提示は、`~/.agents/skills/troubleshoot-environment/references/manual-operations.md`の手動依頼条件に従う。cwdの指定など実行に必要な行は含めてよいが、Coding Agentsが実行できる確認・準備や事後確認を混ぜない。
  3. 事後確認：本人の完了報告後にCoding Agentsが実行して結果を示す。Coding Agentsから確認できない場合だけ、未確認の理由を明記して本人に確認を依頼する。本人の対話シェル限定の確認が必要な場合も、操作本体とは分ける。
- 本人の操作が必要と分かった時点で、手動手順を用意するための確認まで行い、通常の応答本文に理由とコピー可能なコードブロックを示してターンを終了する。質問カード（`request_user_input`・`request_user_input_async`・`AskUserQuestion`など）へコマンドを入れない。本人から実行結果が届くまで、元の作業や独立した別作業を続けない。質問カードではコマンドをコピーしづらく、待機中に作業を続けると本人が対応すべき箇所が埋もれるため。
- 削除・上書き・移動が必要かは、対象の内容・参照先・変更理由・保持すべき差分を調べて判断する。必要なら上記の区分で確認結果と本人操作を分け、対象の絶対パスと明示的なcwdを使う。ただし、ホームへの移動は引数なしの`cd`だけで示す。削除方法は後述の比較手順で選び、削除の実行は本人に依頼する。削除を伴うことだけを理由に方向性を尋ねたり、複雑な操作を一括で本人へ任せたりしない。複雑な手順は確認できる単位に分け、調査後も判断に必要な事実が不明な場合だけ質問する。

削除を依頼する前に、導入元・管理設定・実体と、管理ツールの標準の削除方法をヘルプ等で確認する。`apt remove`・`uv python uninstall`・`uv tool uninstall`・`git worktree remove`など該当する方法があれば提示し、登録情報・依存関係・復旧方法・未コミット変更への影響を直接削除と比較して、どちらを勧めるか理由とともに示す。apt管理でないものへaptを使うなど、管理元の異なる方法を案内しない。標準機能による削除もCoding Agentsは実行せず、本人操作として依頼する。

直接ファイル・ディレクトリを削除する場合は、本人の対話シェルで`rm`→`trash` aliasが働く形の`rm`で示す。ディレクトリには必要に応じて`rm -r -- <対象>`を使う。実行ファイルの絶対パス指定、`rmdir`、aliasを無効にする指定や非対話シェルへの入れ子で置き換えない。対象パスの絶対指定と、削除コマンド自体の絶対パス指定を混同しない。送信前に、本人操作のコードブロックがこの条件を満たすか確認する。

### hook拒否時の証跡

- hookの種類や一致した語にかかわらず、拒否された操作がタスクの遂行に有用なら、拒否だけを報告して終えず、本人による手動実行を依頼する。
- hookが拒否した操作と理由を確認し、目的、対象、変更内容・影響、コピーして使えるコマンドまたは具体的な編集手順を示す。TruffleHogエラー時は、実行の依頼よりAGENTS.mdの停止・詳細報告・本人確認を優先する。
- コマンドの提示前に`mktemp -d /tmp/command-evidence.XXXXXXXX`で試行専用ディレクトリを確保する。提示する手順は、具体的な保存先とcwdを含め、`umask 077`と`set -o noclobber`を設定したサブシェル内で、コマンド・実行条件を`command.txt`、通常コマンドの標準出力・標準エラーを`stdout.log`・`stderr.log`、TTYコマンドの画面出力を`session.log`、終了コードを`exit-code.txt`へ保存する。ログは実行中に画面へも表示する。TTYコマンドは`script -qefc`などでPTYを維持し、`-e`で子コマンドの終了コードを返す。認証情報の値や入力は記録しない。ログをGitへ登録・上書き・削除しない。専用の証跡手順がある操作は、その手順を優先する。
- ログを保存するコマンドには、完了後は「完了した」と返すだけでよいことを伝える。返答後は保存したログと終了コードを読み、結果を確認して元のタスクを再開する。秘密情報を含む原本は全文表示しない。ログの欠落・権限エラー・未完了を成功と扱わず、結果の貼り付けは求めない。
- 編集・削除では対象パスと差分・削除候補を先に示し、完了後は読み取りで結果を確認する。依頼しただけで実行済みと扱わない。
