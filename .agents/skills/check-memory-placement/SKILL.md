保存先や共有方法を決める前に、`~/.agents/skills/write-agent-instructions/references/context-policy.md`を読む。個人情報・社内情報は公開しない。

環境固有の保存先・共有範囲が不明な場合は、ユーザーに確認する。

# メモリの置き場所を確認する

保存前に`references/memory-policy.md`を読み、指示と本人のプロファイルを区別する。

## 書く前の確認

1. 関連する既存スキルを最低一つ読み、担当スキルとそのreferencesを確認する。新規スキルは、既存スキルへの追記やdescriptionの調整で足りない場合に限って検討する。
2. 既存スキルのreferencesとユーザーが指定した記録を確認し、同種の内容があれば既存箇所を更新する。共通指示・スキルへ反映済みの規則をメモリにも重ねて書かない。
3. 保存した規則が必要な操作より前に読まれるか、スキルの入口とグローバルAGENTS.mdの参照条件を確認する。

メモリへの書き込みは、実行環境に適用される許可・保存先の制約に従う。このスキルの呼び出しを、新たな書き込み許可とは扱わない。置き場所を判断できなければ、案と確認が必要な点を短く提示して停止する。

## ディレクトリ構成: 標準構成から逸脱しない

実行環境が生成するメモリの構成を、共有の都合で変更しない。ツールの標準構成と、適用中の上位指示にある制約を確認する。

手動で管理するリンクは、生成済みの実体と対応を確認してから記録する。独自のサブディレクトリや、未生成プロジェクトの保存先を先回りで作らない。

## 複数の作業場所でメモリを共有したいとき

worktreeごとに別のプロジェクトディレクトリが生成される場合も、以下の手順で情報の差を確認して共有する。Git管理下のメモリやリンク設定を編集する前は、`apply-git-strategy`の`references/worktree.md`で作業先を確認する。

1. プロジェクトのパス変換規則を推測して、ディレクトリを先回りで作らない。
2. 実際のセッション起動でプロジェクトディレクトリが生成されるのを待つ。
3. 共有先にない情報を保持してから、リンク切り替えを判断する。削除・置換が必要なら、共通指示に従って手動操作を案内する。
4. 配置を管理するrepoにも同じリンクを記録する。共有先が不明な場合はユーザーに確認する。
