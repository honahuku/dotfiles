# PR説明の構成と確認項目

## PR説明の構成

本文を書く前に、リポジトリのPRテンプレートを確認する。`.github/`、リポジトリ直下、`docs/`のテンプレートと、複数テンプレートのディレクトリを探す。worktreeで見つからない場合は、メインチェックアウトとシンボリックリンク先も確認する。テンプレートがあれば、その見出しと必須項目に沿って書く。

テンプレートがない場合は固定の見出しを作らず、レビュー前に不足する背景・設計判断だけを短く補う。対象外の理由は判断に必要な場合だけ添える。テンプレートがある場合も、必須項目には必要最小限の回答や参照を置き、欄を埋めるための説明を作らない。Test planは後述の「PR本文の確認項目」に従う。

記載する粒度は`review-output`の「PR説明の粒度の例」で確認する。

送信前に全文を読み、文体、一文の長さ、主述の対応、構成、重複を確認する。PRの作成・更新・Ready化前の確認は`prepare-pr-for-review`に従う。


## PR本文の確認項目

PR説明の「確認したこと」「Test plan」「Checks」は、リポジトリのPRテンプレート・CONTRIBUTING・CI・必須手順で定められた確認項目またはCI結果に限る。手元で行った文章校正、技術日本語表記検査、秘密情報検出、個人用lintなどの補助確認は、リポジトリの手順やCIに含まれない限りPR本文へ書かない。補助確認の実施記録が必要なら、PR本文ではなく内部の作業記録に残す。
