# フィードバックを応答方針へ反映する

1. フィードバックを一文で言い換え、認識が変わる余地があれば確認する。
2. 更新先を次から選ぶ。編集先の確認には`apply-git-strategy`の`references/worktree.md`「作業開始」を適用する。ツール間で同一の実体を参照していると決めつけない。
   - 全作業で常に必要な短い規則: 公開dotfilesの`.agents/AGENTS.md`
   - 日本語表現や本人向けの口調: `review-output` スキル
   - 特定作業の手順: 対応する `~/.agents/skills/<name>/SKILL.md`の管理元
   - プロジェクト固有の判断: 非公開資料の該当セクション。公開可能な汎用手順だけをスキルへ置く
3. 既存の同種ルールを探し、重複を増やさず既存箇所を直す。
4. グローバルファイルや個人情報を含む参照資料を変更する前に、差分案をユーザーへ示して確認する。
5. 更新後はスキルの検証を行う。

Coding Agentsが自動生成したメモリDBや生成メモリファイルは、手作業の主要な更新先にしない。
