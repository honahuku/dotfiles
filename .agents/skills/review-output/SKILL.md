# 応答と成果物の確認

このスキルは、応答や文書を読み手に渡せるか確認する。主述と修飾の対応、説明の過不足、説明先をまたぐ重複、投稿先に合う文体を扱う。技術文書の構成・事実関係・出典・検証結果を組み立てる手順は`write-technical-docs`が担当する。

## 依頼に応じた使い分け

| 依頼・作業 | 使うスキルと順序 |
| --- | --- |
| 会話の回答、進捗報告、一般的な連絡文を確認する | `review-output`。技術文書の執筆手順は追加しない |
| 仕様書・技術説明・実験レポート・PRやIssueの技術的な本文を作成・修正する | `write-technical-docs`で内容を組み立て、`review-output`で読み手に必要な情報と文章の明確さを確認する |
| 技術文書の主述・修飾・重複だけを直す | `review-output`で確認する。仕様・根拠・説明構成も変える必要があれば`write-technical-docs`を使う |
| 日本語を自然な表現へ整える | `yomiyasu`。技術的な意味や条件は変えない |

執筆前には説明先をまたぐ重複だけを先に確認し、送信・保存前には下表から必要な確認を選ぶ。内容の不足や矛盾を見つけた場合は、該当する執筆手順へ戻る。確認済みで変更のない資料を、相互参照だけを理由に読み直さない。

## 確認に使う資料

| 確認対象 | 資料 |
| --- | --- |
| 本人操作の依頼、検査結果の報告、コミットメッセージ案の提示 | `~/.agents/docs/common/manual-operations.md`の依頼前の検証提示。依頼文がなくても適用し、対象作業のツール出力と本文を照合する |
| PRの未返信コメントの調査、コメント対応の着手前、返信案の作成前 | `references/output-review.md`のPRコメントの返信状況 |
| 応答の送信前・文書の保存前。短文、見出し、表、箇条書きも含む | `references/output-review.md`の主述・対象・修飾の確認 |
| 文書・PR・コメント・Notion等の執筆前と送信前 | `references/output-review.md`の説明先をまたぐ重複チェック |
| 長文成果物の独立した確認 | `references/adversarial-review.md` |
| 名前の扱い、投稿先別の文体、確実性や書式の詳細 | `~/.agents/docs/common/output-policy.md`の該当セクション |
| 日本語の推敲 | `yomiyasu` |

数行の短い応答には長文用の独立レビューを追加しない。本人向けの文面支援でも質問に直接答え、経緯から書き始めない。
